8. Unnecessary Joins & Cartesian Products:
   - For EVERY table or alias in FROM and JOIN, find where else in the query it
     is used. An alias that appears ONLY in its own ON clause -- never in SELECT,
     WHERE, HAVING, GROUP BY or ORDER BY, and not needed to bridge two tables
     that lack a direct relationship -- is an idle join. Report it: it changes
     the row count and therefore every aggregate, without adding information.
   - Report as a Cartesian product, always: CROSS JOIN, a comma-separated FROM
     list of two or more tables, a JOIN with no ON clause, ON TRUE, or an ON
     clause that compares a column to a constant instead of equating keys.
   - An ON clause must equate keys named by a relationship in the Relevant
     Schema. If a join equates two columns that merely share a name or a type
     and no such relationship exists, report it as an invented join.
   - Composite keys: if a relationship names several column pairs and the ON
     clause matches only some of them, report the missing pair -- the join
     multiplies rows.
   - Fan-out: if two DIFFERENT one-to-many child tables are joined as siblings
     off the same parent, report it. Each inflates the other, so any COUNT or
     SUM in the query is wrong. The fix is a scalar subquery or a pre-aggregated
     derived table per child, not DISTINCT.
   - Conversely, do NOT report a join that is doing a real job, and do not
     demand a join be rewritten as EXISTS when the query displays columns from
     the joined table. Judge by whether the table is used, not by style.
