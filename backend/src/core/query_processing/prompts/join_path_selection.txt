Table selection has already chosen which tables the question is about. Your job
is to decide HOW those tables should be connected, by choosing from a list of
join paths that were enumerated from the database's real foreign keys.

Question: {question}
Subjective concepts (entities): {subjective}
Objective concepts (metrics, filters): {objective}

Selected tables: {selected_objects}

{candidates_context}

HOW TO CHOOSE:
- Every path listed above is structurally valid. You are choosing which one is
  SEMANTICALLY correct for this question, not which one is possible.
- When two paths connect the same two tables through different intermediate
  tables, pick the one whose intermediate tables match the question's meaning.
  Read their descriptions. A question about purchase payments goes through
  orders; a question about recurring billing goes through subscriptions.
- When two paths connect the same tables through the SAME intermediate tables
  but join on different columns, pick the one whose columns match the question.
  A question about departures joins on the origin column, arrivals on the
  destination column.
- Prefer the shortest path that is semantically correct. Do not add hops that
  the question does not ask for.
- Choose the FEWEST paths that connect what the question needs. Never choose
  two paths between the SAME pair of tables -- one route between two tables is
  all a query can use, and extra routes only drag in tables the question never
  asked about. If the question needs A, B and C, pick one path for A-B and one
  for B-C, not every candidate that happens to touch them.
- Do not justify a path by saying its intermediate tables are "related" or
  "relevant". Choose it only if the question's meaning requires going that way.
- A path marked STANDALONE connects nothing: it is a single table with no
  foreign-key route to the others. Choose it only if the question really can be
  answered from that table on its own. If that table is not relevant to the
  question, leave it out and it will be dropped.
- Do NOT choose paths through tables that are unrelated to the question just to
  make something connect.

RULES:
- Do NOT generate SQL, MongoDB syntax, or code.
- Choose ONLY path ids that appear in the list above. Never invent a path id.
- Keep reasoning brief (2-3 sentences), then immediately output the JSON block.
- Output ONLY valid JSON matching this schema:
{{
  "chosen_paths": ["<path_id>", "<path_id>"],
  "reason": "<brief justification for why these paths fit the question>"
}}
